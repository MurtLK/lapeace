# LAPEACE Technical Specification

Version 1.0 · Contract version `1.0.0` · November 7 2026

This is the implementation contract for [PRD.md](PRD.md). The repository currently contains planning documents and assets, not a running application. The structure, commands, schemas, endpoints, and tests below are required implementation targets. Task T00 creates and validates them before dependent code is integrated.

## 1 Architecture and explicit choices

Use Python 3.12 with FastAPI for the API and offline data pipeline; React and TypeScript with Vite for the browser interface. Keep benchmark artifacts as versioned JSON/JSONL files. No database, message queue, external map service, or generic LLM dependency is needed for the first release.

The browser calls only the local backend. The backend reads validated artifacts, resolves allowlisted audio IDs, and calls ElevenLabs. Development uses a Vite `/api` proxy to a loopback FastAPI service. A production build can be served by FastAPI after API routes are registered. Bind to loopback by default; public hosting requires a separate design review.

The service prototype is turn-based Scribe plus a constrained dialogue state machine plus TTS. It is not a streaming telephone integration or an ElevenLabs Agents implementation. A reviewed scenario grammar recognizes one missed-collection flow; unmatched or uncertain input asks for clarification. It never invents municipal policy or submits a real ticket.

T00 pins compatible package versions and commits the lockfiles. Python dependencies: FastAPI, Uvicorn, Pydantic, httpx, python-multipart, pytest, and jsonschema. Frontend dependencies: React, TypeScript, Vite, a test runner, and Testing Library. Include a browser flow runner for integration checks. Use ffmpeg/ffprobe for bounded media inspection and conversion; document the installed prerequisite. Avoid adding infrastructure without a requirement.

## 4 Contract and artifact rules

All public JSON responses and exported artifact envelopes contain `schema_version: "1.0.0"`. UTC timestamps use ISO 8601. IDs are stable strings, scores finite numbers or null, and lists have deterministic ordering. Schema validation rejects unknown enum states and mismatched references. T00 provides JSON Schemas, TypeScript types, and labelled minimal examples; API and UI agents must not invent extra fields independently.

### Core records

| Record | Required fields and interpretation |

| `Review` | `sample_id`, `reviewer`, `reviewed_at`, `status` (`pending`, `accepted`, `excluded`), `reason`, `meaning_review` (`verified`, `unverified`), `reference_override` or null, `override_reason` or null |
| `Run` | `run_id`, `manifest_sha256`, `settings_sha256`, `provider`, `model_id`, `settings`, `normalization_version`, `created_at`, `origin` (`provider`, `fixture`), `request_count`, `submitted_audio_seconds`, `status` (`pending`, `running`, `partial`, `complete`, `failed`) |
| `TranscriptResult` | `sample_id`, `run_id`, `status` (`pending`, `succeeded`, `failed`), `prediction_raw` or null, `provider_request_id` or null, `completed_at` or null, `error_code` or null, `word_edits` or null, `reference_words` or null, `character_edits` or null, `reference_characters` or null, `wer` or null, `cer` or null |

Use `speaker_key="saa:<recording stem>"` as the archive's recording identity proxy, not proof of deduplicated biological identity. Canonical cohort IDs map explicitly to the crosswalk, for example `mandarin` → `Mandarin Chinese` → `home_mandarin`. A review override preserves the supplied reference and creates a new manifest version; all results using the old reference remain traceable.

`manifest.json` contains the schema version, selection config, source hashes, selected Samples, and reserves/exclusions. `runs/<run_id>/run.json` contains Run; `results.jsonl` contains one latest record per selected sample, with request attempts retained separately. `summary.json` contains cohort aggregates and Provenance. `wards.json` contains all 11 Ward records and Provenance. Write a temporary file then atomically rename it; never expose a half-written artifact.

`active-run.json` explicitly selects the reviewed `run_id`, manifest hash, and artifact paths for presentation. Do not select results by filesystem modification time or merge records from different runs. Exporting it is an operator action after validation. If it is absent, show census context and manifest records with pending results; no measured finding or index is implied. Development fixtures require an explicit fixture mode and cannot be selected as an approved provider run.

`origin` describes evidence provenance, while API `execution_mode` is `live`, `cached`, `fixture`, `scripted_replay`, or `unavailable`. Reading stored provider results is `cached` with `origin=provider`. Toy fixtures never become measured results simply by being cached.

## 5 Transcription and metric behavior

The provider adapter sends multipart `file` plus configured `model_id` to `POST https://api.elevenlabs.io/v1/speech-to-text`, with server-side authentication. Set `language_code=en`, `diarize=false`, `tag_audio_events=false`, and `no_verbatim=false` for the archive pilot. Do not use reference text as keyterms or rewrite the predicted transcript. Preserve the provider's raw response locally; score its original transcript text. Revalidate the configured model and account access before the paid run.

Cache key: SHA-256 of audio bytes plus canonical provider/model/request settings; never put the API key into hashes or logs. Manifest and normalization hashes belong to scored artifact identity, so the same transcription can be rescored without another paid call.

Normalization `en_v1`: Unicode NFC, Unicode casefold, replace each Unicode punctuation-category character with a space, collapse whitespace, trim. Do not remove diacritics, transliterate, translate, expand numbers, or repair a prediction. WER tokenizes this result by whitespace. CER removes whitespace from this result and scores remaining Unicode code points. Document that punctuation splitting can affect contractions. Future languages need their own recorded normalization choices; do not compare raw cross-script WER as though it had identical meaning.

WER is word-level Levenshtein distance divided by normalized reference word count. CER is character-level Levenshtein distance divided by reference character count. Group metrics sum edit counts and reference denominators across successful samples before division. Do not average percentages or clamp reported WER/CER. Delta is cohort WER minus baseline WER, reported in percentage points in the UI.

An empty normalized reference is a validation failure and excluded with a reason. A successful provider response with empty transcript is a valid all-deletions prediction (WER/CER 1 for a nonempty reference). A provider failure is not empty speech: keep transcript and metrics null and count the failure. Show denominator and completion counts for partial aggregates.

Offline stages implement documented CLI targets `validate`, `select`, `transcribe`, `score`, `export-wards`, and `export-demo` under `python -m lapeace_data`. `transcribe --dry-run` estimates selected duration and requests without network access. Live mode requires an explicit `--live` flag and configured credentials. Run two clips first, inspect outputs, then authorize the remaining frozen pilot within the configured cap. Cache hits consume no provider requests.

Default pilot cap: 45 submitted attempts and 1,800 audio seconds, including the initial smoke clips and any replacements. Count attempts conservatively; a timeout may still have been billed. Stop at either cap. No hidden paid retries. Honor a retryable response only through a recorded, operator-triggered retry that remains inside the cap.

`contracts/v1/imported.schema.json` adds `ImportedRun` and `EvaluatedWards` without changing the older offline-only `Run`/`Wards` schemas. Results and summaries reuse `TranscriptResult` and `Summary`. The app must load this extension for Buzz results and preserve its limitations. The ward index requires 40 successful reviewed records, positive group denominators, provider evidence and an attested uniform profile; otherwise indices remain null. Fixtures never produce a measured index. No automatic `active-run.json` promotion or app integration is implied. See `docs/pipeline/buzz.md` for the current run and reproducible commands.

Use the corrected ward table as authoritative for ward counts; use `geo_language_long.csv` for explanatory detail only after validating it agrees. Ward 10 must have its corrected flag set. Validate 11 unique ward IDs and positive `population_language_base`. Zero-population neighbourhoods are excluded if a later neighbourhood export is added.

For comparison group g, let `r_g` be its corpus WER, `b` the Canadian English corpus WER, and `gap_g = min(1, max(0, r_g - b))`. For ward w let `H_wg` be corrected home-language count for g and `C_w = sum_g H_wg`. Then:

```text
index_w = 100 * sum_g(H_wg * gap_g) / C_w
coverage_of_top14_w = C_w / top14_nonofficial_home_language_speakers_w
```

Publish an index only when the 40 selected clips have succeeded and passed review under the same settings profile, and all comparison and baseline denominators are nonzero. Otherwise all ward indices are null with `index_status=incomplete`; census context remains viewable. If `C_w=0` or the coverage denominator is zero, return null for the affected field, never divide by zero. Use only the same fixed three comparison groups across wards. Sort ready rows by index descending, then covered count descending, then ward ascending; incomplete rows sort by ward.

Retain unbounded raw WER separately; the cap applies only to index contributions. An index of zero can reflect no observed excess error over baseline; it is not missing evidence and not a guarantee of service access. Display the covered population separately from the index. It is never an estimate of people who will be misunderstood. Census home language and archive first language are different variables, and this weighting is a documented proxy.

## 7 API contract

All application endpoints use `/api/v1`. Successful response envelopes include `schema_version`, `execution_mode`, and `data`. List endpoints return all pilot records or all 11 wards; pagination is unnecessary for this bounded release. Evidence APIs are read-only; paid benchmark generation runs through the operator CLI.

| Method and path | Input | Output |
|---|---|---|
| `GET /health` | None | API readiness and supported schema version; no secret values |
| `GET /capabilities` | None | Evidence availability, service modes, enabled reviewed languages, recording formats and limits |
| `GET /samples?cohort_id=...` | Optional known cohort | Samples and latest linked TranscriptResults; unknown cohort is 422 |
| `GET /samples/{sample_id}` | Stable ID | Sample, result, provenance, and relative audio URL |
| `GET /samples/{sample_id}/audio` | Stable allowlisted ID | Correct media content type and seek/range support; JSON envelope does not wrap bytes |
| `GET /cohorts` | None | Latest cohort summary with one run/settings identity |
| `GET /wards` | None | Eleven Ward records and provenance |
| `POST /service/sessions` | JSON `{language, mode, scenario_id?, consent}` | ServiceSession; live requires consent, replay requires a known scenario ID |
| `POST /service/sessions/{id}/turns` | Multipart `audio`, `expected_revision`, `request_id` | Updated ServiceSession after a recorded turn; live mode only |
| `POST /service/sessions/{id}/actions` | JSON `{action, expected_revision, request_id}` | Updated session; actions: `confirm`, `correct`, `cancel`, `replay_next`, `retry_prompt` |
| `GET /service/sessions/{id}/prompt/{prompt_id}` | Session and prompt IDs | Prompt audio only if generated or validly cached; no arbitrary file paths |
| `DELETE /service/sessions/{id}` | Session ID | JSON acknowledgement, with session and temporary media removed |

`ServiceSession` fields: `session_id`, `language`, `mode` (`live`, `scripted_replay`), `revision`, `state`, `scenario_id` or null, `transcript` or null, `draft` (`intent`, `collection_type`, `location`), `prompt` (`prompt_id`, `text`, `audio_url` or null, `audio_status`), `receipt` or null, `expires_at`, `last_error` or null. Each prompt records its provider/model or reviewed replay provenance on the backend. Use fictional locations in demo scenarios.

Errors use `{schema_version, error: {code, message, retryable, request_id}}`. Use 404 for unknown IDs, 409 for revision/state conflicts, 410 for expired sessions, 413 for excessive bytes, 415 for unsupported media, 422 for invalid values or excessive duration, 429 for configured spend limits, 502 for provider rejection, 503 for unavailable credentials/cache, and 504 for provider timeout. Omit provider internals and source absolute paths. A service failure preserves the last valid state and exposes no invented result.

## 8 Dialogue behavior and media handling

`content/scenarios.json` has `schema_version` and a `languages` array. Each language entry contains `language`, `enabled`, `reviewer` or null, `reviewed_at` or null, `prompts`, `lexicon`, and `scenarios`. Prompt keys are `greeting`, `ask_collection_type`, `ask_location`, `confirm_template`, `manual_help`, `cancelled`, and `completed`; template substitutions are limited to validated draft fields. The lexicon lists missed-collection phrases, aliases for `garbage`, `recycling`, and `organics`, and allowed fictional demo locations in that language. Matching rules are case/spacing-normalized literal phrases, not code from the content file.

Each scenario has `scenario_id`, `kind` (`success`, `ambiguous`, `provider_failure`), reviewed turn transcripts and optional allowlisted audio asset IDs, expected states/draft values, and expected final state. Transcript-only examples are scripted fixtures, not measured model predictions. A language with no fluent review remains `enabled=false`. T60 drafts prose and provisional JSON immediately; T61 validates and finalizes content after T00 freezes the corresponding schema.

States: `awaiting_request`, `clarifying`, `awaiting_confirmation`, `completed`, `cancelled`. Session creation returns a reviewed greeting and starts `awaiting_request`. For the missed-collection scenario the draft requires `intent=missed_collection`, collection type, and a fictional demo location. The reviewed language-specific matching rules populate only supported values. Unrecognized or missing fields move to `clarifying`; ask at most two clarification turns, then offer manual help and cancellation rather than guessing.

A complete draft moves to `awaiting_confirmation` and displays the exact interpreted request. `confirm` is allowed only there and produces a `SIMULATED-...` receipt plus the message “Demo only. No municipal request was submitted.” `correct` clears the draft and prior confirmation, then returns to `awaiting_request`; `cancel` is allowed before completion and never creates a receipt. Completed and cancelled sessions reject additional mutation except repeated idempotent requests. Spoken affirmations are not automatic consent to submit; use an explicit confirmation control for this release.

Use unique `request_id` values and a monotonically increasing `revision`. Check the idempotency record before revision/state validation: retrying the same ID and payload returns the prior response without another paid call even if its original revision is now stale. Reusing an ID with different content is 409. A new request with stale revision is 409. Serialize mutations per session; two workers must not process the same paid turn concurrently. Single-process memory is sufficient for local demo state; do not imply multiworker durability.

If transcription fails, preserve the prior draft/state. If TTS fails after a turn has been understood, preserve the updated state, prompt text, and draft with `audio_status=failed`; do not ask the user to repeat a successfully transcribed turn. `retry_prompt` retries synthesis for that same current reviewed prompt, subject to budget, and never changes the draft or creates a second receipt. It is idempotent under the request rules above. Retrieval GETs never generate speech or incur cost.

Scripted replay advances only through `replay_next` over reviewed scenario assets and identified cached provider prompts. It does not accept new audio. Label the transcript as scripted and the speech as cached ElevenLabs output where applicable. If that cache is absent, show reviewed text and unavailable audio, not a generated-looking replacement.

Browser recording uses supported MediaRecorder MIME types reported by capabilities; offer upload when recording is unsupported or denied. Accepted uploads: WAV, MP3, FLAC, Ogg, and WebM only after signature and decode validation. Maximum 10 MiB and 45 seconds per turn. Probe and convert in bounded subprocesses; do not trust filename or browser MIME alone. Use generated temporary names and no user-supplied URLs. Source sample playback resolves only manifest IDs under the extracted root.

Live prompt synthesis calls `POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id}` with reviewed `text`, configured `model_id`, and `output_format=mp3_44100_128`. Cache by text, voice, model, and settings. Choose a permitted stock voice; do not clone dataset speakers. Validate speech quality per enabled language. Do not send `language_code` to a model that does not support it; the documented multilingual v2 model does not support that parameter.

Use a 60-second provider timeout and clear progress UI, not an unsupported real-time latency claim. A provider failure offers explicit retry or text/manual fallback. For service sessions default to at most 10 live STT attempts and 20 prompt-generation attempts per `LAPEACE_BUDGET_ID`. Persist counters atomically in ignored `data/cache/budgets/`; a restart with the same budget ID retains spending. A new budget ID requires an explicit operator decision. An exhausted budget prevents new live calls; retries count unless the idempotency record or valid cache satisfies them without network access.

## 9 Configuration and data protection

T00 creates `.env.example` with empty secret placeholders and these configuration names: `LAPEACE_DATASET_SOURCE`, `LAPEACE_ARTIFACT_ROOT`, `LAPEACE_SERVICE_MODE`, `LAPEACE_BUDGET_ID`, `ELEVENLABS_API_KEY`, `ELEVENLABS_STT_MODEL`, `ELEVENLABS_TTS_MODEL`, and `ELEVENLABS_VOICE_ID`. Default to replay and no network calls. Pin actual model settings in the run manifest; keep account-dependent model or voice selection configurable.

Never expose secrets through `VITE_*`, browser bundles, source control, request logs, or health endpoints. Bind locally, restrict development origins to the documented app origin, and reject unexpected origins for mutating routes. Never serve the full dataset directory as public static content. Browser content is rendered as text, not raw transcript HTML.

Show consent before each live session. Do not collect actual addresses, payment data, or identity documents. Delete uploaded turn media in a finally block after processing; close sessions and clear transcript state on reset or after 15 minutes of inactivity. Sweep stale temporary files at startup. Do not cache user recordings or their transcripts as benchmark artifacts. Provider retention follows the configured account and service terms; local cleanup is not a third-party retention guarantee.
