## Five implementation rules

1. **Let the supplied logo establish the palette.** HIG branding says, “Defer branding to content.” Use its navy for strong text, blue for the dashboard action, teal for restrained supporting accents, and near-white/cool-tinted surfaces. These color roles are LaPeace design choices. Keep the actual asset's proportions and colors; allow enough space that its white image background feels intentional. One clear header identity and a quieter footer treatment are sufficient. Do not convert the homepage into a wall of saturated gradients. [Apple Branding](https://developer.apple.com/design/human-interface-guidelines/branding)

2. **Make bento sizes express importance.** HIG layout says, “Be prepared for text-size changes.” Give the existing reference-passage explorer the dominant card, then smaller cards for recognition evidence, Mississauga language context and clarifying service requests. Keep “Open dashboard” the obvious primary action. On narrow widths, stack these in the same meaningful DOM order, allow text/card height to grow and keep all content available at 200% zoom. A desktop grid can vary card spans; mobile should not inherit fixed card heights. Bento sizing, breakpoints and spacing are design choices, not Apple specifications. [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Collections](https://developer.apple.com/design/human-interface-guidelines/collections)

3. **Keep motion small and causal.** Apple says, “Add motion purposefully, supporting the experience without overshadowing it.” Use immediate pressed feedback and short transitions for actual passage selection or menu changes. Keep reading content stable; avoid looping waves, staged entrance delays, scroll hijacking and hover-dependent content. Respect `prefers-reduced-motion`; any translucent navigation needs a legible solid fallback. Use solid or softly tinted bento content surfaces rather than glass on every tile. [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion), [Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Apple Design alternative](https://www.ui-skills.com/skills/emilkowalski/apple-design/llms.txt)

4. **Make actions work with touch and keyboard.** HIG says, “Offer sufficiently sized controls.” As a web design choice, retain at least 44 CSS px hit areas for primary buttons and mobile navigation; Apple's native point measurements are not CSS requirements. Keep visible `:focus-visible` outlines, real anchors for navigation, real buttons for state changes, an accessible menu name/state and keyboard-operable passage controls. Maintain heading hierarchy and the skip link. Decorative geometry should be hidden from assistive technology; the linked logo needs an accessible LaPeace name without duplicated nearby text. Verify text contrast against each actual surface and preserve browser zoom. [Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

5. **Persuade through clear evidence and honest labels.** HIG writing says, “Be clear.” Keep the existing project scope, source links and dashboard destinations. State that the visual acoustic geometry is illustrative; do not imply it is measured speech, playable audio or live processing. Distinguish census home-language context from accent-recognition evidence. Add no invented success rate, user count, testimonial or partner logo. Use concise titles and concrete link labels so the grid explains the project before asking visitors to inspect its evidence. These provenance safeguards also follow the project's supplied facts. [Apple Writing](https://developer.apple.com/design/human-interface-guidelines/writing), [project scope](../../PRODUCT.md)

## Review handoff

Check the finished homepage at wide and narrow widths, with keyboard-only navigation, 200% zoom and reduced motion. Confirm that `/dashboard` and the existing evidence/community/clarification destinations still work; confirm no overflow, cropped logo, unreadable tinted text, hidden mobile content or faux interactive visualization. The homepage introduces evidence; the dashboard owns the detailed analysis.
